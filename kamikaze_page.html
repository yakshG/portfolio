OVERVIEW

Kamikaze is a 2-4 player local split-screen tactical deathmatch shooter. Players compete in a 3-minute deathmatch across four maps using a modular weapon system (knife, pistol, rifle) where highest score wins.

I was the solo programmer for the first half of development and later transitioned into Lead Programmer.

MY CONTRIBUTIONS

Core Gameplay Systems

  • Centralized all match flow inside GameMode:
    • Score tracking per player
    • Timer management with countdown display
    • Win condition logic (highest score at match end)
    • Randomized respawn handling
  • Designed and implemented health system with damage detection and death handling.

Local Multiplayer

  • Built the full local multiplayer pipeline:
    • Multi-controller input handling (supports 2-4 players)
    • PlayerController → Pawn possession with proper timing
    • Player-specific spawn assignment
    • Split-screen viewport assignment

Weapon Systems

  • Designed a modular weapon system using a shared base class.
  • Implemented three weapon types via Blueprint inheritance:
    • Knife - melee weapon with 3 attack animations
    • Pistol - semi automatic ranged weapon
    • Rifle - automatic ranged weapon
  • Built weapon switching system and ammo management.

Animations

  • Helped record motion-capture animations for melee attacks.
  • Integrated and refined animations using Unreal's Animation Blueprint.
  • Set up animation state machines for movement, attacking, and death states.

Character Selection Locking

  • Designed a first-come-first-serve character selection system:
    • Selected characters lock immediately
    • UI dynamically updates character availability across all controllers
    • Lock state tied to player index for proper tracking

Steam Build & Publishing

  • Handled production builds and resolved packaging issues.
  • Managed final Steam deployment.

TECHNICAL CHALLENGES

Challenge: Pawn Possession in Local Multiplayer

Problem: PlayerControllers were failing to properly possess spawned pawns due to incorrect initialization timing in Unreal's lifecycle.

Solution: Traced Unreal's actor lifecycle flow and implemented post-initialization function calls to ensure proper order of:

  • PlayerController initialization
  • Pawn spawning
  • Possession execution

This resolved timing issues and ensured all players could reliably control their characters across multiple match restarts.
