OVERVIEW

Kamikaze is a 2-4 player local split-screen tactical deathmatch shooter. Players compete in a 3-minute deathmatch across four maps using a modular weapon system (knife, pistol, rifle) where highest score wins.

CONTRIBUTIONS

    • Win condition logic (highest score at match end).

POST MORTEM

Challenge: Pawn Possession Timing in Local Multiplayer

Problem: Non-default PlayerControllers were failing to properly possess spawned pawns due to incorrect initialization in Unreal's actor lifecycle.

Solution: Traced Unreal's actor lifecycle flow and implemented possession inside a post-initialization call to ensure the correct order:

  • PlayerController initialization
  • Pawn spawning
  • Possession execution

This ensured all players could reliably control their characters.

Challenge: Merge Conflicts in a Multi-Programmer Team

Problem: With three programmers working simultaneously on Blueprint assets, merge conflicts on .uasset files were unavoidable. The binary format meant conflicts couldn't be resolved manually.

Solution: Used smart locks in Plastic SCM, which prevented simultaneous edits on the same asset. Combined with clearer communication around file ownership, this eliminated the problem for the remainder of the project.
